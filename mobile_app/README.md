# Smart OPD — Patient Mobile App (Flutter, Android)

Patient application of the *Smart Digital Queue Management System for Hospital OPD
with AI-Based Waiting Time Prediction and Branch Recommendation* (Section 4.2.1 of the
FYP documentation). Patients register, join a doctor's OPD queue from home, follow their
token live with an AI waiting-time estimate, get a branch recommendation when a queue is
congested, book appointments, track linked laboratory/pharmacy tokens, receive in-app
notifications, review their visit history and rate a visit.

Everything the app sends and receives follows [`docs/API_CONTRACT.md`](../docs/API_CONTRACT.md)
(REST under `/api`, Socket.IO on the same origin, backend-issued JWT).

## 1. Requirements

| Tool | Version |
|---|---|
| Flutter SDK (stable) | 3.22 or newer (Dart 3.4+) |
| Android SDK / Android Studio | an emulator or a phone with Android 6.0+ |
| Smart OPD backend | running on port 4000 (see `backend/`) |

Check your setup with `flutter doctor`.

## 2. First-time setup

This folder contains the app's source (`lib/`, `test/`, `pubspec.yaml`,
`analysis_options.yaml`) and a hand-written `android/app/src/main/AndroidManifest.xml`
(internet and location permissions, cleartext HTTP for local development). The rest of
the Android Gradle project (wrapper, `build.gradle`, `MainActivity`, launcher icons,
styles) is generated by Flutter:

```bash
cd mobile_app
flutter create . --platforms android --project-name smart_opd
flutter pub get
```

`flutter create .` only adds the files that are missing. It does not overwrite the
existing `lib/`, `test/`, `pubspec.yaml`, `README.md` or `AndroidManifest.xml`. (It skips
`test/widget_test.dart` because that file already exists, so no counter-app sample test
is added.)

## 3. Run

1. Start the backend on the development machine (in `backend/`: `npm install`, then
   `npm start`). It listens on `http://localhost:4000`. For a demo outside clinic hours,
   start it with `DEMO_ALWAYS_OPEN=true` so that doctors who have a schedule that weekday
   accept patients at any time of day.
2. Start an Android emulator (or connect a phone) and run:

```bash
flutter run --dart-define=API_URL=http://10.0.2.2:4000
```

`10.0.2.2` is how the Android emulator reaches `localhost` on the host machine, and it is
also the default when `API_URL` is not given. On a **physical phone**, use the computer's
LAN address instead (phone and computer on the same Wi-Fi network, firewall open for port
4000):

```bash
flutter run --dart-define=API_URL=http://192.168.1.20:4000
```

The login screen and the Profile tab show which server the app is using.

## 5. Real-time updates and notifications

* **Socket.IO** (`lib/services/socket_service.dart`): after login the app connects to the
  backend origin with `auth: { token: <jwt> }` over WebSocket. The server puts the socket
  in `user:<id>`, and the My Token screen also subscribes to `token:<id>`. Events only say
  that something changed; the app then re-fetches the REST resource (`GET /tokens/active`,
  `GET /tokens/:id`, `GET /notifications`). Rooms are re-joined after a reconnect, and the
  token screen polls every 45 s while the socket is offline.
* **In-app notifications (FR-11):** the `notification` socket event shows a SnackBar with a
  *VIEW* action that opens the token, and refreshes `GET /api/notifications`, which drives
  the unread badge on the bell. Opening the app from the background also re-fetches tokens
  and notifications.
* **Version note:** the backend uses socket.io 4.8. The `socket_io_client` 2.x line only
  supports servers v3.x–v4.6.x according to the package's compatibility table, so this app
  uses `socket_io_client` 3.x, which has the same API.

### Adding push notifications (FCM) later

Push notifications are not part of this build, so the app has no Firebase dependency and
needs no `google-services.json`. The backend already accepts a device token, so FCM can be
added without backend changes:

1. Create a Firebase project, add an Android app with package name
   `com.example.smart_opd` (or your final application id) and run
   `flutterfire configure` (FlutterFire CLI). This places `google-services.json` in
   `android/app/` and generates `lib/firebase_options.dart`.
2. Add the packages: `flutter pub add firebase_core firebase_messaging`.
3. In `main()`, before `runApp`, call
   `await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);`.
4. After a successful login (`AuthState._startSession` in `lib/state/auth_state.dart`),
   request permission with `FirebaseMessaging.instance.requestPermission()` (this also
   covers Android 13's `POST_NOTIFICATIONS`), read the token with
   `FirebaseMessaging.instance.getToken()` and send it with the existing
   `OpdApi.registerDeviceToken(token)`, which calls
   `POST /api/notifications/device-token` with `{ "fcmToken": "<token>" }`. Do the same in
   `FirebaseMessaging.instance.onTokenRefresh`.
5. Handle `FirebaseMessaging.onMessageOpenedApp` (and `getInitialMessage()`) by calling
   `openTokenScreen(tokenId)` from `lib/navigation.dart` when the message data carries a
   `tokenId`.

The in-app list and badge keep working unchanged, because the backend also stores every
notification for `GET /api/notifications`.

## 6. Location and privacy (FR-08, NFR-05)

`ACCESS_FINE_LOCATION`/`ACCESS_COARSE_LOCATION` are declared in the manifest but the app
asks for them only when the patient taps *Use my location* on the Recommendations screen,
after a short explanation. The coordinates are sent once as `lat`/`lng` query parameters of
`GET /api/recommendations` and are never stored on the phone or by the server. If the
permission is refused or location is switched off, branches are ranked by predicted wait
and congestion only. If the permission is blocked permanently, the app offers a button
that opens the phone's settings.

## 7. Tests and static analysis

```bash
flutter analyze
flutter test
```

The tests need no network or device:

* `test/widget_test.dart`: estimate-range formula and formatting, the range text widget and
  its spoken label, status chips, the doctor availability badge, the called-token notice
  and the star rating input.
* `test/home_screen_test.dart`: the Home screen against an in-memory fake API (`MockClient`
  from `package:http/testing.dart`) using contract-shaped JSON. It covers the active token
  shown first with its position, now serving and estimate range, the *Join a queue*
  prompt, the error state, and grouping of linked tokens by visit.
* `test/models_test.dart`: parsing of every contract object the app reads (TokenDetail,
  User, Appointment, slots, doctor rows, recommendations, visits, notifications), using the
  contract examples and responses captured from the real backend.

## 9. Troubleshooting

| Symptom | Fix |
|---|---|
| "Cannot reach the hospital server" | Is the backend running? On a phone, use the PC's LAN IP in `API_URL` and allow port 4000 in the firewall. |
| `CLEARTEXT communication not permitted` | Keep `android:usesCleartextTraffic="true"` for local HTTP; use HTTPS for production and remove it. |
| Doctor shows *Not accepting now* | The session is over or not today; start the backend with `DEMO_ALWAYS_OPEN=true` for demos. |
| My Token shows *Offline* | The socket could not connect; the screen still refreshes every 45 s and on pull-to-refresh. Check `API_URL` and that the backend allows WebSocket connections. |
| Sent back to the login screen | The saved JWT was rejected (for example `JWT_SECRET` changed or the database was re-created); log in again. |
